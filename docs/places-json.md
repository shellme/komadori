# 場所の空き状況 JSON の作り方（スクリプトを直す AI への指示）

コマドリ（日程調整アプリ）に貼る「場所の空き状況」の JSON を作るスクリプトを直すための指示書です。
下の「依頼文」と「仕様」をまとめて AI に渡してください。

---

## 依頼文

スタジオの空き状況を集めて JSON を書き出すスクリプトがあります。この JSON は日程調整アプリ「コマドリ」に貼り付けて使います。
次の仕様に合わせて、スクリプトを直してください。

やりたいこと：
- 平日の練習は人数が少ないことがあるので、**部屋ごとの適正人数**を JSON に入れ、アプリが「この人数ならこの部屋」と判断できるようにする
- 職場の近くで探せるように、**グループ（エリア）を街の単位に細かくする**（今は「渋谷」に恵比寿も入っている）
- 職場の近くのエリア（**恵比寿・赤坂**）のスタジオと、**少人数向けの小さい部屋**も集める対象に入れる（今は20帖以上の部屋だけになっている）

直したら、最後の「できあがりの確かめ」をすべて行い、結果を報告してください。

---

## 仕様

### 全体の形

```json
{
  "format": "availability",
  "version": 1,
  "asOf": "2026-11-13T22:37:00+09:00",
  "places": [
    {
      "id": "noah-ebisu-cst",
      "name": "ノア恵比寿 Cst 26帖",
      "group": "恵比寿",
      "capacity": { "min": 5, "max": 10 },
      "note": "26帖 / 恵比寿駅 徒歩2分",
      "url": "https://www.studionoah.jp/noahweb/webs/chart/ebisu/cst/"
    }
  ],
  "slots": [
    { "place": "noah-ebisu-cst", "date": "2027-02-10", "free": ["19:00-22:00"] }
  ]
}
```

- `format`・`version`・`slots` の形は今のまま変えない
- `asOf` は**空き状況を集めた実際の日時**を、日本時間の ISO 形式（`2026-11-13T22:37:00+09:00`）で入れる。アプリは「11/13 22:37時点」と出す
- `places` の各部屋に **`capacity` を足す**。**`group` の付け方を変える**（下に詳しく）
- 文字コードは UTF-8。JSON として正しく読めること

### places の各項目

| 項目 | 要る | 中身 | 上限 |
|---|---|---|---|
| `id` | ○ | 部屋を見分ける文字。`slots` の `place` と同じにする。**部屋を足しても変わらないもの**にする（予約 URL から作る。例：`noah-ebisu-cst`）。並び順の番号（`r0` など）は使わない | 80文字 |
| `name` | ○ | 画面に出す部屋の名前（例：`ノア恵比寿 Cst 26帖`）。同じ名前の部屋を2つ作らない | 80文字 |
| `group` | ○ | エリア（下の「グループの付け方」） | 200文字 |
| `capacity` | 任意 | 適正人数（下の「適正人数の付け方」） | — |
| `note` | 任意 | 広さ・最寄り駅・受付の決まりなど（今のまま）。人数はここに書かない | 200文字 |
| `url` | 任意 | 予約ページ。`http://` か `https://` で始まるもの | 500文字 |

### グループの付け方（変える）

- **店舗のある街の名前を1つ**入れる。店舗名に地名があればそれを使う（`ノア恵比寿` → `恵比寿`、`ノード水道橋` → `水道橋`）。なければ最寄り駅の名前を使う。「駅」は付けない
- 1つの部屋に1つだけ。「・」でつないだ複数の地名（今の `秋葉原・水道橋`）は使わない
- 同じ街はいつも同じ書き方にする（`恵比寿` と `恵比須` を混ぜない）
- スクリプトの中に **店舗 → 街の対応表** を持ち、そこから付ける。対応表にない店舗が出てきたら、止めずに `その他` にして、最後に一覧で知らせる

今のデータに当てはめると、次のようになる。

| 店舗 | 今のグループ | 新しいグループ |
|---|---|---|
| ノア初台 | 新宿 | 初台 |
| ノア高田馬場 | 新宿 | 高田馬場 |
| ノア新宿、ノード新宿 | 新宿 | 新宿 |
| ノア代々木 | 新宿 | 代々木 |
| ノア中野 | 新宿 | 中野 |
| ノア渋谷本店、ノア渋谷2号、ノア渋谷3号 | 渋谷 | 渋谷 |
| ノア恵比寿 | 渋谷 | 恵比寿 |
| ノア秋葉原 | 秋葉原・水道橋 | 秋葉原 |
| ノード水道橋 | 秋葉原・水道橋 | 水道橋 |
| ノア池袋 | 池袋 | 池袋 |
| （新しく足す）赤坂のスタジオ | — | 赤坂 |

### 適正人数の付け方（足す）

- 形は `"capacity": { "min": 3, "max": 6 }`。**整数**（1〜999）で、`min` ≦ `max`
- 片方だけでもよい。「6人まで」なら `{ "max": 6 }`、「4人から」なら `{ "min": 4 }`
- スタジオのページに適正人数が載っていないので、**人が決めた2つの表**から付ける
  1. **帖数の区切りの表**（`CAPACITY_BY_JO`）：「◯帖以上は ◯〜◯人」。部屋の名前の「◯帖」から引く
  2. **部屋ごとの上書き**（`CAPACITY`）：部屋の名前で引く。1より優先する
- 表の数字は人（サークルの実感）が決める。AI が勝手に決めたり変えたりしない
- どちらの表にも当たらない部屋は `capacity` を書かない。最後に「人数が未設定の部屋」として一覧で知らせる
- 形がおかしい値（整数でない、`min` が `max` より大きい）は、書き出す前にエラーで止める

```python
# 帖数の区切り：大きい順に見て、最初に当たったもの（数字は人が決める）
CAPACITY_BY_JO = [
    (24, {"min": 7, "max": 12}),
    (17, {"min": 5, "max": 8}),
]
# 部屋ごとの上書き（部屋の名前で引く。区切りの表より優先）
CAPACITY = {
    # "ノア赤坂 CSst 17帖": {"min": 3, "max": 6},
}
```

アプリでの使われ方：候補の時間に来られる人数（参加できる人＋調整が必要な人）に合う部屋を先に出し、人数より大きい部屋は「広め」として後ろに出す。人数が `max` より多いときは「◯人には狭い場所 ◯か所」と数だけ出す。`capacity` のない部屋は、どの人数の候補にも出す。

### 集める対象（広げる）

- 恵比寿・赤坂のスタジオを対象に入れる
- 20帖未満の小さい部屋も入れる（少人数の平日練習に使うため）。どこまで小さい部屋を入れるかは、帖数の区切りの表でいちばん小さい区切りを目安にする
- 数の上限を超えないこと：**部屋は300まで、`slots` は5000行まで**。超えそうなら、期間を短くするか、対象のスタジオを減らす

### slots（今のまま）

- `place`：`places` の `id` のどれか
- `date`：`YYYY-MM-DD`
- `free`：空いている時間帯の配列。`"HH:MM-HH:MM"`（24時間、2けた）。日をまたぐ深夜は `"22:00-26:00"` のように26:00まで書ける
- 空きのない日は行を出さない（または `free: []`）

## できあがりの確かめ

直したスクリプトで JSON を書き出し、次をすべて確かめて報告してください。

1. JSON として読める。`format` は `"availability"`、`version` は `1`
2. `slots` の `place` が、すべて `places` の `id` のどれかと同じ
3. `places` の `name` に同じものがない
4. `capacity` があるものは、`min`・`max` が整数で `min` ≦ `max`
5. `group` の一覧と、それぞれの部屋の数（例：`恵比寿 3部屋、赤坂 2部屋…`）。`その他` があれば、その店舗の名前
6. `capacity` が未設定の部屋の一覧
7. 部屋の数（300以下）と `slots` の行数（5000以下）
8. `note` に人数を書いていない。`group` に「・」や「駅」が入っていない

## アプリ側について（メモ）

- コマドリは `capacity` を読み、候補に人数に合う部屋を先に出す。結果の画面では、グループを複数選んでしぼれる（例：恵比寿と赤坂）
- `capacity` の形がおかしい部屋は、人数なしとして扱う（部屋そのものは使う）
