# コマドリ（komadori）日程調整アプリ 設計

最終更新：2026-11-13
サイトは https://komadori.web.app （Firebase のプロジェクト ID は komadori-app）

## 名前
- **コマドリ**（ローマ字 komadori）。みんながそろう「コマ（時間の枠）」を「取る」アプリ。鳥の駒鳥にもかけて、アイコンは小鳥にできる
- URL：`komadori.web.app`。リポジトリ名も `komadori` にそろえる（Firebase のプロジェクト ID は `komadori-app`）
- 候補にしたもの：そろう・あいとき・かさなる・ひまあわせ・SlotMatch・Slotter・モナカ（意味の伝わりやすさと親しみやすさで選んだ。komadori.com・komadori.app には別のサイトがある）

## なぜ作るか
- もとは軽音サークルのバンドの練習日を決めるため。スタジオの空きと全員の都合を重ねて見たい
- 調整さんや Google カレンダーと違うところが、バンドに限らず役に立つ
- サークルに入っていない人どうし（友だち、仕事の打ち合わせ）でも、URL を送るだけで使えるようにしたい

## 調整さん・Google カレンダーとの違い
| | 調整さん | Google カレンダー | このアプリ |
|---|---|---|---|
| 聞き方 | 候補日を先に決めて ○△× | 相手の予定の空きを見る | **期間だけ決めて、日ごとに「何時から何時まで空いているか」** |
| 答える人 | URL を知っている人 | 同じ会社・共有している人 | URL を知っている人（ログインなし） |
| 見つけたいもの | ○が多い日 | 全員が空いている時間 | **「2時間そろう枠」「3時間そろう枠」を良い順に** |
| 外せない人 | なし | なし | **必須の人**（この人が来られない枠は出さない）・**優先する人**（来られる枠を先に、来られない日はほかの人で並べる） |
| 入れる手間 | 候補の数だけ | 予定を全部入れておく | **いつもの予定でまとめて入れる**（例：平日 19〜22時は空き、土日は 13〜18時）→ 1日ずつ直す |
| 場所の空き | なし | なし | **場所の空き状況を貼り付けると重ねて見られる**（スタジオ・飲食店・会議室など） |
| 決まったあと | なし | 予定ができる | **候補の文面をコピーして、LINE などで知らせる**（決定はこのアプリに記録しない） |

## 決めたこと
- **既定は「期間だけ決める」**：候補日は先に決めない。ただし、**除外する日・時間帯**を先に決めておける（下の「除外」）
- **ログインなし**：URL を知っている人なら誰でも答えられる（調整さんと同じ）。なりすましは防げない代わりに、誰が・いつ変えたかの履歴を残す
- **作った人だけの管理用 URL**：期間・時間の設定、場所の貼り付け、候補の文面のコピーは管理用 URL（推測できない長い鍵つき）からだけ
- **日程の決定はこのアプリでは扱わない**：役割は候補をしぼるところまで。決めた日時は、候補の文面をコピーして LINE などで知らせる。スタジオの予約は別のサイトで取り、取れずに変えることもあるので、アプリに決定を記録しても手間が増えるだけだった（2026-11 に「この枠に決める」を外した）
- **時間の刻みは作るときに選ぶ：30分（既定）か1時間**（スタジオは30分単位で取れることが多い。ざっくり決めたいときは1時間）。刻みに合わせて、回答の時間帯は内側に丸め（開始は切り上げ・終わりは切り捨て）、除外の時間帯は少しでもかかる枠を外す
- **場所の空き状況は貼り付け**：スタジオに限らない形にして、形式を文書にする（下の「貼り付けの形式」）
- **ほかのアプリとはデータを共有しない**：つなぐのはコピペ（文面・JSON）だけ
- **出欠はこのアプリでは扱わない**：候補の文面を書き出して、ほかのアプリに貼る

## 使う人と流れ
| 人 | すること |
|---|---|
| 呼びかける人 | 調整を作る（名前・期間・何時から何時の間で・何時間集まりたいか）→ 答える用の URL を LINE などで送る。管理用 URL は自分で取っておく |
| 答える人 | URL を開く → 名前を入れる（前に答えた名前があれば選ぶ）→ いつもの予定でまとめて入れる → 1日ずつ直す（参加できる・調整が必要・参加不可、ひとこと） |
| 呼びかける人 | 結果を見る：全員の重なり（日×時間の表）、「2時間そろう枠」のよい順、必須の人・最低人数でしぼる、場所の空きを重ねる → 候補の文面をコピーして LINE などで知らせる |

### ユーザーストーリー（振る舞いのテストの元）
- S-1 調整を作る：期間（〜最長3か月）、1日の範囲（例 9:00〜23:00）、集まりたい長さ（30分刻み、複数可）、メモ。作ると「答える用」と「管理用」の2つの URL が出る
- S-1b 除外を決めておく：作るとき（あとからでも）に、使わない日・時間帯を入れる。答える画面ではその日・時間は灰色で選べず、結果の枠にも出ない
- S-2 答える：名前を入れて答える。同じ端末なら次は名前を選ばずに自分の行が開く。ほかの端末からは名前を選んで直せる（履歴に残る）
- S-3 いつもの予定でまとめて入れる：曜日・祝日ごとに「入れない／参加できる／調整が必要／参加不可」と時間帯
- S-4 1日ずつ直す：時間帯をなぞって選ぶ（スマホは押して範囲を伸ばす）。日ごとにひとこと
- S-5 結果を見る：日×時間の表（人数の濃さ）、長さごとのよい枠の一覧。必須の人・最低人数・曜日（平日夜／土日）でしぼる
  - 優先する人：来られる日が限られる人に合わせる。並べ方は、優先する人が枠のあいだずっと来られる（● か △）→ 一部の時間だけ重なる → 人数 → 空いている場所の数。重なる枠は1つにまとめるが、優先する人が来られる枠と来られない枠は別に出す（一部だけ重なる枠を横に並べて比べられるように）。選んだ人はその端末に覚える
  - 週ごとのいちばんよい枠：練習の頻度（週1回など）を決めるときのため、結果のいちばん上に、月曜はじまりの週ごとに上の並べ方でいちばんよい枠を1つずつ出す
  - 場所の並べ方：人数に合う順（ふつう）か広い順（遠くから来る人がいる日など）。その端末に覚える
  - 投稿する候補：候補をいくつか選び、場所とメモを付けて「◆候補① 日時 / 場所 / メモ」の文面をまとめて作る（メンバーには LINE や Slack で知らせ、そこで絞っていく）。その端末に覚え、決定は記録しない
  - AI に相談する：お願い・条件のひな形・設定・回答（人ごと・日ごとの ●△×）・場所の空き・アプリが出した候補（日ごとに上位3つ）を1つの文面にしてコピー。細かい条件（頻度・本番前の回数・会員証など）をアプリの機能にせず、AI に文章で頼めるように。人数の重なりの計算はアプリでして渡す（AI は数え間違えやすい）。名前を「メンバーA」…に置き換えられる。ファイルの書き出しではなくコピーにしたのは、スマホの AI アプリには貼るほうが手軽なため
  - 優先する人・週ごとのまとめ・場所の広い順・投稿する候補・AI に相談するは、管理用の URL で開いたときだけ（回答する人には要らない）
- S-6 場所の空きを重ねる：空き状況を貼り付けると、枠ごとに「空いている場所」が出る。場所の種類・メモ（広さなど）でしぼる
- S-7 知らせる：管理用 URL で、候補の「文面をコピー」で1行の文面（日時・名前・空いている場所）をコピーし、LINE などに貼る
- S-9 名前の一覧を貼る：作るときに「呼びたい人」の名前を1行に1人で貼れる（`*` を付けると必須）。まだ答えていない人がわかる

## データの形（Firestore）
```
polls/{pollId}                      pollId は推測できない 20 文字
    title, note, from: "2026-12-01", to: "2026-12-31", dayStart: "09:00", dayEnd: "23:00", step: 30,   step は 30 か 60
    durations: [120, 180], holidays: ["2026-12-23"],
    dayType: "all" | "weekend" | "weekday",   対象の日（なければ all）
    exclude: [                        除外（下の「除外」）。どれも同じ形
      { kind: "rule", from: "2026-12-24", to: "2026-12-24", note: "クリスマス" },
      { kind: "rule", from: "2027-01-01", to: "2027-01-31", weekdays: [1, 2, 3, 4, 5], holiday: "skip" },
      { kind: "rule", weekdays: [1, 2, 3, 4, 5], holiday: "skip", start: "09:00", end: "12:00" },
      { kind: "rule", from: "2026-12-12", to: "2026-12-12", start: "18:00", end: "23:00", note: "別のライブ" } ],
    invited: [{ name, required }],   呼びたい人（任意）
    adminKeyHash, createdAt, expireAt   期間の終わりから 90 日で消す
  ├ people/{personId}               答えた人
  │   name, required, note, updatedAt, device
  │   days: { "2026-12-05": { sure: ["13:00-18:00"], maybe: ["19:00-21:00"], ng: false, note: "" } }
  │   └ log/{id}                    変更の履歴（端末・時刻・変えた日）
  └ places/current                  貼り付けた場所の空き状況（下の JSON と同じ形）
```
- 時間帯は "HH:MM-HH:MM" の文字列の配列で持つ（30分刻みに丸める）。読みやすさと、貼り付けの形式と同じにするため
- 管理用の鍵はハッシュだけ保存。管理の操作は、鍵を Cloud Functions で確かめてから書く（ルールだけでは鍵を確かめられないため）
- 答える人の書き込みは、匿名ログイン（端末ごと）＋ device を必ず入れる

## 除外（先に決まっている使えない日・時間帯）
候補日は先に決めないが、「この日は会場が使えない」「平日の昼は無理」のように最初から外したいものは、呼びかける人が先に入れておける。

- **対象の日**（`dayType`）：すべての日（既定）／土日祝だけ／平日だけ。たいていはこれだけで足りる
- **使わない日・時間帯**（`exclude`）：例外を1行に1つ。どれも同じ1つの形の決まり（`kind: "rule"`）で持つ

| 部分 | 書き方 | データ |
|---|---|---|
| いつ（任意） | `12/24`・`1/1-1/5`・`1月` | `from`・`to`（なければ期間全体） |
| どの日（任意） | `平日`・`土日`・`土日祝`・`毎日`・`月 水`・`月 水 祝`・`祝` | `weekdays`（なければ毎日）・`holiday` |
| 何時（任意） | `9:00-18:00` | `start`・`end`（なければ1日まるごと） |
| ひとこと（任意） | `別のライブ` | `note` |

- いつ・どの日のどちらかは要る。例：`12/24 クリスマス`、`1月 平日`（1月は土日祝だけ）、`平日 9:00-18:00`、`12/12 18:00-23:00 別のライブ`
- **祝日の扱いは1つに決める**：曜日や「平日」「土日」で書いたものは祝日にかからない（`holiday: "skip"`）。祝日も外したいときは「祝」を足す（`"add"`。「土日祝」はこれ）。祝日は日本の祝日を初めから入れておく
- 前の形（`date`・`weekday`・`days`・`time`・`range`）は、読むときに同じ形に直す（`logic.js` の `normRule`）。前の「月 水」は祝日でも当てはまっていたので、`holiday: "any"` として前と同じに読む。設定を編集して保存し直すと、今の決まり（祝日にかからない）になる
- 除外した日は回答の一覧に出さない（どの日かは画面の上の「使わない日・時間帯」に出る）。除外した時間は灰色になり選べない
- 結果の枠にも出さない。あとから除外を足したときは、その時間に入っていた答えは消さずに残す（除外を外せば戻る）
- 参加者の答えの「参加不可」とは別もの：除外は全員に共通で、呼びかける人だけが決める

## 貼り付けの形式（場所の空き状況）
スタジオに限らず「場所ごとに、空いている時間帯」を表すものなら何でも使える（スタジオ、飲食店の予約できる時間、会議室、体育館、カラオケ）。
次の4つのどれかを貼り付ける（ファイルの読み込みも可）。形はアプリが自動で見分ける。

### 1. 1行に1つ（手で書くとき）
```
スタジオA 新宿 32帖	2026-12-05	13:00-18:00, 19:00-22:00
スタジオA 新宿 32帖	12/6	10:00-12:00
居酒屋まる	12/5	18:00-23:00	4〜8人
```
- 区切りはタブ。タブがないときは「場所 日付 時間帯」を空白で区切る（場所の名前に空白があるときはタブを使う）
- 4つめ以降は自由なメモ（広さ・人数・値段など）。5つめに http から始まる URL があれば、予約ページのリンクにする

### 2. 表（スプレッドシートから縦長でコピー）
1行目が見出し。見出しの名前で列を見分ける（順番は自由）。タブ区切り・カンマ区切りのどちらでもよい
| 見出し | 必須 | 中身 |
|---|---|---|
| 場所 | ○ | 場所の名前 |
| 日付 | ○ | 2026-12-05、2026/12/5、12/5（年がなければ調整の期間から決める） |
| 空き | ○ | 時間帯。複数は「,」「、」「/」「／」で区切る |
| メモ | | 広さ・人数・値段など（しぼり込みの文字検索に使う） |
| URL | | 予約ページ |
| グループ | | 店舗・駅・エリアなど。結果でまとめて表示する |

### 3. 表（日付×場所の横長。今のスタジオの空き状況の形）
```
日付	スタジオA 32帖	スタジオB 20帖
グループ	新宿	代々木            ← 任意の行（1列目が「グループ」「URL」「メモ」の行は、その列の場所の情報）
URL	https://…	https://…
2026-12-05	13:00-18:00 / 19:00-22:00	受付前
2026-12-06	10:00-12:00
```
- 1行目の1列目が「日付」。2列目からが場所
- 空きのマスが空・「×」・「-」・「受付前」・「満」なら、その日は空きなし

### 4. JSON（ほかのツールから渡すとき）
```json
{
  "format": "availability",
  "version": 1,
  "asOf": "2026-11-11T09:00:00+09:00",
  "places": [
    { "id": "a32", "name": "スタジオA 32帖", "group": "新宿", "capacity": { "min": 7, "max": 12 }, "note": "32帖・ドラム2台", "url": "https://example.com/a" }
  ],
  "slots": [
    { "place": "a32", "date": "2026-12-05", "free": ["13:00-18:00", "19:00-22:00"] }
  ]
}
```
- `place` は places の `id`（なければ `name` でもよい）
- `capacity` は場所の人数（任意。`min`・`max` の片方だけでもよい）。候補の枠に来られる人数（参加できる＋調整が必要）に合う場所 → 人数のない場所 → 広めの場所（人数が下限より少ない）の順に出し、入りきらない場所（上限より多い）は数だけ出す。よい枠は、合う場所と人数のない場所の数で比べ、同じなら広めの場所の数で比べる（少人数で大きい部屋を使うのはよくあるので、広めは使える場所として扱う。広めを外すと、どの部屋も合わない人数のときに場所のない時間が候補になってしまった）
- 結果の画面では、場所のグループを複数選んでしぼれる（どれかに入れば残す）
- スクリプトで作るときの決まりは [places-json.md](places-json.md)
- `asOf` は「いつ時点の空き状況か」。結果の画面に「〇時点。予約前に必ず確かめてください」と出す

### 共通の決まり
- 時刻は 24時間・「HH:MM」。「9:00」も可。日をまたぐ「22:00-26:00」は 26:00 まで書ける（深夜パック）
- 時間帯の区切りの「-」は「〜」「~」「–」でもよい
- 30分刻みに丸める（開始は切り上げ、終わりは切り捨て。例 13:10-15:50 → 13:30-15:30）
- 読めなかった行は、行番号と理由を出して飛ばす（全部を止めない）
- 1行目が「日付」の2次元配列の JSON も、3 の形として読める。部屋の名前の「〇帖」はメモに移す

## 書き出しの形式（ほかのアプリへ）
### 候補の枠の文面
```
2026-12-05 13:00-15:00 バンド練習 @スタジオA 32帖
```
- 1行に1つ。「日付 時間帯 名前 @場所」（@場所は任意）
- ほかのアプリでこの1行を読めば、予定の下書きにできる
- 候補を複数書き出すときも同じ形で複数行

### 呼びたい人の一覧（貼り付けで入れる）
```
*アキ
ベン
チカ
```
- 1行に1人。先頭の `*` は必須。ほかのアプリのメンバーの一覧をこの形で書き出せば、そのまま貼れる


### 調整のまるごと（JSON）
- `{ "format": "poll", "version": 1, ... }`：設定・答え。ほかのツールで集計したいとき用

## 画面
- **トップ**：説明と「調整を作る」。この端末で最近見た調整の一覧（端末に保存）
- **作る**：名前・期間・1日の範囲・長さ・メモ・呼びたい人（任意・貼り付け）
- **答える**（`/p/{pollId}`）：自分の名前、いつもの予定、日ごとの時間帯（スマホで押しやすい大きさ）、結果へのリンク
- **結果**（同じ URL のタブ）：日×時間の表、よい枠の一覧（長さ・必須・最低人数・曜日でしぼる）、場所の空き
- **管理**（`/p/{pollId}#admin=鍵`）：設定の変更、場所の空き状況を貼る、候補の文面のコピー、消す
- 見た目はさっぱりした道具の見た目（UI の決まりは [ui-rules.md](ui-rules.md)）

## 技術
- Hosting＋Firestore＋匿名ログイン＋Cloud Functions（管理用の鍵の確認、期限切れの削除）
- 計算（時間帯の読み取り・丸め、重なり、よい枠、貼り付けの読み取り）は1つのファイルにまとめてテストを付ける。今の `hoursFromText`・`bestWindows` を30分刻みにして持っていく
- 検索には出さない（noindex）。調整の中身は URL を知っている人だけ

## 段階
1. 最小の形（入れた）：作る（除外の日・時間帯も）・答える（1日ずつ）・結果の表とよい枠・候補の枠の文面のコピー
2. いつもの予定でまとめて入れる、必須の人・最低人数・曜日でしぼる、呼びたい人の貼り付け（入れた。必須の人は「調整が必要」なら来られるとして数える。結果の画面で押して切り替えられ、その端末の表示だけ変わる）
3. 場所の空き状況の貼り付け（4つの形式）と重ねて見る（入れた。貼るのは管理用 URL から。保存は Cloud Functions の setPlaces が鍵を確かめてから。候補ごとに空いている場所、マスの下線、グループ・文字でしぼる、回答の画面に「この時間で空いている場所」、コピーの文面に @場所）
